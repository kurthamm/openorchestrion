The experience

Music appliance, not DAW.

OpenOrchestrion hides Linux, MIDI plumbing, scheduling, metadata, and routing behind one responsive interface used from the attached touchscreen or any household browser.

Find your music

Search, combine filters, save favorites and playlists, and inspect encoded instruments before playing. AI is reserved for a future optional interface; the current browser has no assistant panel.

Choose intelligently

Smart Stations score real indexed performances using metadata, compatibility, favorites, quality, history, no-repeat windows, composer diversity, familiarity, energy, and explicit relaxation diagnostics.

Play locally

The Raspberry Pi owns the queue, clock, MIDI timeline, routing, device cleanup, and WebSocket state. Internet access is never part of musical timing.

Playback modes

From solo piano to two engines.

SOLO_PIANO

Expressive piano performance on one preferred engine.

MULTI_INSTRUMENT

GM/multichannel arrangements distributed by program family and device capability.

PIANO_DUET

Four-hands material with separable parts routed across sound engines.

TWO_PIANO

Independent Piano I and Piano II destinations on one synchronized timeline.

DUELING_PIANO

Purpose-built arrangements that exchange roles, phrases, or accompaniment.

DISTRIBUTED

Reserved for future coordinated room endpoints.

Non-destructive rendering

Every queue can preserve the original arrangement, render pitched parts as piano, or apply selected General MIDI channel overrides. The source file and its SHA-256 identity never change.

Reference appliance

Small computer. Ordinary keyboards. Surprisingly deep system.

The reference software target is a Raspberry Pi 5 running Raspberry Pi OS 64-bit, FastAPI, SQLite, Mido/python-rtmidi, Chromium kiosk mode, and systemd.

  • Headless or 7-inch touchscreen appliance
  • One process owns playback and WebSocket sequence state
  • Boots with no MIDI hardware attached and reports a degraded state
  • Friendly LAN discovery with optional openorchestrion.local
  • Secure local-admin configuration for hosted AI credentials
  • Verified backup/restore with catalog rebuild and rollback protection

Keyboard-as-sound-engine model

The keyboard is selected primarily for MIDI receive behavior, tone quality, polyphony, multitimbral capability, speakers/outputs, reliability, and price. Human key feel is not the purchasing center of gravity.

The current Pi uses a Casio WK-220. Its reported playback checklist and loaded headless timing evidence are recorded in the repository. The new CT-X700 and two-engine work remain deferred; acoustic synchronization is not yet measured.

Music and rights

A starter library you can explain, not a mystery MIDI dump.

The public repository contains 18 starter files; the reference owner’s personal library is not distributed. Bundled music is content-addressed and carries separate evidence for composition rights and the rights of the specific MIDI performance/arrangement. Unknown or personal-use material does not become redistributable by wishful metadata.

Verified/open

Evidence-backed source, composition basis, file license, redistribution status, and required attribution.

Personal

User-imported material can remain fully usable without being asserted safe for repository redistribution.

Fail closed

CI audits tracked MIDI repository-wide. A file without established evidence cannot quietly ship because it lives in a different folder.
