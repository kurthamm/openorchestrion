# OpenOrchestrion 0.1.0

The first numbered public release of the single-keyboard MIDI appliance includes
the listening-room interface, durable playlists and player controls, qualified
library acquisition, instrument details, title repair, and verified backup tools.

## New-user experience

Open **Music library → Add music**, choose reviewed sources, and start a bounded
check. The server prepares a genuinely empty library, checks up to five candidates
per selected source, and shows additions, quality exclusions, duplicates and source
failures. Progress survives leaving the page. Retry resumes the existing discovery
history; no existing songs or player settings are cleared. Nightly acquisition is
an explicit administrator opt-in.

## Downloads and installation

- The wheel installs the application, web UI and appliance deployment templates.
- The source ZIP includes documentation and the separately licensed 18-file starter
  catalog. It does not include the owner's personal library.
- The source distribution supports standard Python build workflows.
- `install-appliance.sh` installs or upgrades the appliance from the wheel.
- `SHA256SUMS` and `release.json` identify the artifacts and exact source commit.

Follow [versioned installation and upgrades](../releases.md) or
[getting started](../getting-started.md). Linux/Python 3.11–3.13 and a compatible MIDI
output are required for the appliance; the browser does not synthesize sound.

## Compatibility and limits

Existing MIDI bytes, IDs, queues, favorites, playlists and settings are preserved.
The new guided job record is operational state; it does not change admission policy.
Acquisition now locks the library itself across both CLI and browser runs. Stop
older acquisition workers before upgrading so every writer uses the same lock.
An existing library without v2 admission/duplicate history needs the documented
operator migration; the browser refuses to reset or silently adopt it.

Source availability can change. Admission checks MIDI structure and documented
performance evidence; it is not an acoustic listening certification. Source usage
terms still apply. The 18-file starter collection is a separate exploration set,
not a claim that all 18 pass the current listening quality gate.

The WK-220 is the current single-keyboard reference. CT-X700 and device-specific
two-engine work, the AI browser interface, physical touchscreen/enclosure validation,
and fresh-OS acceptance on a separate Pi remain outside this release's evidence.
The HTTP service trusts the household LAN; remote access needs an authenticated proxy.

## Release validation

Publication runs the full CI suite on Python 3.11–3.13, browser behavior checks,
lint, schema/rights contracts and a non-editable wheel smoke test before creating
the version tag. It builds and inspects the exact downloadable wheel and publishes
checksums. Guided-acquisition tests exercise real qualification/publication with
controlled MIDI input, duplicate retry, source validation, cross-origin rejection,
shared writer locking, preservation of existing unseeded collections and shutdown.

The Pi validation suite passed 770 tests. In a separate empty library, the packaged
application was driven through Add music in Chromium: the selected SMD source
admitted five performances, reported completion, and made them available without
a server restart. The reference personal library was not used for this test.
