# White Paper

The original design exploration was documented as **Networked Player Piano Requirements & Architecture White Paper v1.1** before the project became OpenOrchestrion.

The current publication source is:

- [OpenOrchestrion White Paper v2.0](OpenOrchestrion_White_Paper_v2.md)

The v2 paper is Markdown-first so it can stay aligned with the living repository architecture. It covers the implemented appliance stack: AI Music Concierge, Smart Stations, durable sidecars/catalog/history, rights-aware starter repertoire, server-owned playback, synchronized multi-device routing, non-destructive rendering, setup/discovery, Raspberry Pi packaging, CI, and verified backup/restore.

It also distinguishes implemented software from hardware evidence that is still pending. Final PDF/DOCX publication, hardware photographs, measured Pi/keyboard timing, and demo media should be generated after the physical reference build is validated rather than frozen into the paper as design assumptions.

The living technical documents under [`docs/`](../README.md) remain authoritative for detailed contracts and implementation behavior. The white paper is the narrative publication layer built from those sources.
